For VS Code and Cursor

Obsidian-style notes, inside VS Code.

Lumiere is a better Markdown editor for VS Code that keeps the good properties of Obsidian: notes render as you type, wikilinks resolve the way Obsidian resolves them, and embeds, callouts, properties, an outline, a graph and backlinks are there. It reads PDFs too.

Try it in your browser Install from Marketplace View on GitHub

The browser demo opens a GitHub Codespace with VS Code, Lumiere and a sample vault. It needs a GitHub account, and Codespaces includes a free monthly allowance on personal accounts. Lumiere is not affiliated with Obsidian.

What it does

Every feature is a plugin you can switch off. Where Lumiere differs from Obsidian, the differences are listed below.

Writing

Formatting renders in place. Its Markdown shows only around the caret, then hides again.

  • Live Preview or Source mode, one command apart. VS Code keeps the text, saving and undo.
  • Obsidian's Markdown: wikilinks, embeds, callouts, tags, ==highlights==, %%comments%%, footnotes, math, block ids and task lists.
  • Rich blocks: tables you edit as a grid, foldable and nested callouts, MathJax, Mermaid diagrams that follow the VS Code theme, and code blocks with syntax highlighting and a Copy button.
  • Properties: a typed editor for a note's front matter (text, list, number, checkbox, date, tags, aliases).
  • Obsidian's editing keys (Ctrl/Cmd+B, I, K), smart lists, paired brackets, find and replace, rich-text paste as Markdown, and an optional Vim mode.

Linking and navigation

Links resolve by Obsidian's rules: case-insensitive, with .md optional, ./ and ../ from the note's folder and other paths from the vault root.

  • Suggestions as you type for notes, aliases, headings, blocks, tags and the sections of a PDF. The [[ suggestions also work in VS Code's own text editor.
  • Follow, preview, go back. Alt+Enter follows the link at the caret, Ctrl/Cmd+Enter opens it in a new tab, Ctrl/Cmd-hover previews the target, and Go Back in Note returns to where you jumped from.
  • Renames update links. Rename or move a note in VS Code and links to it are rewritten in other notes (it asks first by default).
  • Links to notes that do not exist yet are dimmed, and following one creates the note. 
[[Note]]               a note
[[Note|alias]]         shown as "alias"
[[Note#Heading]]       a section
[[Note#^block]]        one block

![[Note#Heading]]      embed a section
![[paper.pdf#page=3]]  embed a PDF page
![[tasks.base]]        embed a Bases view

Embeds

Pull other notes, files and live views into a note, the way you do in Obsidian.

  • Notes, headings and block ids, shown in place.
  • Obsidian Bases files as table, card or list views.
  • PDFs: one page inline, with page buttons and an Open button that opens the reader.
  • Images with sizes, keyboard resizing and a viewer, plus audio and video.
  • Mermaid diagrams, drawn in your theme's colours.
  • HTML files as a card whose Open button shows the page in VS Code's Integrated Browser.

Vault tools

A folder with .obsidian/ is a vault; without one, the workspace folder is. Lumiere reads the vault's settings for link format, new-note and attachment folders and more.

  • Quick Switcher over notes, aliases and unresolved links.
  • Markdown Outline in the Explorer, with Go to Heading. Drag a heading to move its section.
  • Backlinks and Outgoing Links views, with unlinked mentions (off by default; the sample vault turns them on).
  • Tags view, and Search Vault with Obsidian's search syntax, plus query blocks that show live results in a note.
  • Vault graph, global or local.

A PDF reader, with notes

Lumiere PDF is built on EmbedPDF and the PDFium engine, running in a worker. Single pages or two-page spreads, continuous or page by page, zoom and fit, find, and internal and web links.

  • Annotations. Select text and right-click for Highlight, Underline, Strikeout, Squiggly, or a highlight with a note written in Markdown. Marks are kept outside the PDF, in .lumiere/pdf-annotations/; the PDF changes only if you run Save Annotations into This PDF.
  • Backlinks from notes. A note's link to paper.pdf#page=3#:~:text=… paints a highlight on that passage; clicking it opens the note.
  • Bookmarks as an outline in the Explorer, following the page you read.
  • Dark paper that follows the theme, and a reader that comes back at the same page and zoom when a paper is rebuilt.

Made to work with agents

Links that point an agent back to the exact lines of a note or the exact page of a PDF.

  • Copy link to this. In a note it copies a link to the selected lines with the passage quoted under it. In a PDF it copies a link to the page with the selected text.
  • Straight into the chat, if you want it. Send a note's passage to Cursor's chat, VS Code's chat, Claude Code or Codex.
  • Open what an agent printed. Open Copied Agent Reference opens those lines, and Open Location… opens that page.
  • IDE context. Copy IDE Context builds a packet with the active note or PDF, the selection, open tabs and diagnostics, for Claude Code and Codex.
  • A public API (v1) lets other VS Code extensions add markers, actions, link handlers and code block renderers. 
@notes/a.md#12-18      lines 12 to 18 of a note
@papers/a.pdf#page=3   page 3 of a PDF

Why inside VS Code

Obsidian's editing is why people keep notes in Markdown. It is also a separate application. Lumiere puts it in the editor you already work in, beside everything VS Code gives you.

  • Git

    Change bars beside the line numbers, a peek with the change's diff and Revert, and a side-by-side rendered diff of two versions of a note.

  • Agents

    Claude Code, Codex, Cursor's chat and VS Code chat, with links back to the exact lines or page.

  • Terminals, tasks and extensions

    Terminals, tasks and the extensions you already use, next to your notes.

  • Remote and Codespaces

    SSH, Dev Containers and Codespaces: VS Code runs the extension on the machine that holds your files. That is how the browser demo works.

Differences from Obsidian

Lumiere is not Obsidian and does not cover all of it. It uses Obsidian 1.15.0 as its behaviour reference and never copies its code, styles or assets. Read this before you move a vault over.

  • No Reading view. A note is in Live Preview or Source mode. Ctrl/Cmd+E switches between Lumiere and VS Code's own text editor instead.
  • HTML pages are not drawn in a note. An embedded or linked .html file opens in VS Code's Integrated Browser where the window has one. The embed is a card with Open and Open as Text.
  • A plain click on a rendered link reveals its source. Ctrl/Cmd-click or Alt+Enter follows it.
  • Some embeds differ. A PDF embed shows one page, not Obsidian's whole viewer. YouTube links are not embedded.
  • Native views, not panes. The outline, backlinks, tags and search results are Explorer views. There is no Dataview, and the graph has no 3D view and refuses a vault of more than 2,000 notes or 20,000 links.
  • Not implemented: Canvas, bookmarks, Publish and Sync.
  • No community plugins or themes. Colours follow your VS Code theme, and the .obsidian CSS snippets you have enabled load. Extensions to Lumiere are VS Code extensions that use its API.
  • Some keys are left to VS Code. Obsidian's Ctrl/Cmd+O and Ctrl/Cmd+D are not bound, and in Cursor, Ctrl/Cmd+K and L stay Cursor's.
  • Three editor defaults differ on purpose. Readable line length is off, the inline title is off and line numbers are on. Each is a setting.
  • Not in VS Code for the Web. Lumiere runs in a Node extension host, so it does not run in vscode.dev or github.dev. A Codespace works because the extension runs on its server.

Every row of the comparison, with how it was checked and on which Obsidian version, is in PARITY.md. Automated checks do not establish visual parity, and many rows there are marked as not yet compared by hand.

Use it on your own notes

  1. Install Lumiere (t04dJ14n9.lumiere) from the Marketplace, or search for it in the Extensions view.
  2. Open a folder of notes. An existing Obsidian vault works as it is.
  3. Run Use Lumiere for Markdown in This Workspace from the Command Palette, so *.md files in that folder open in Lumiere. It is an option, not the default, so it does not take over every README you open.
  4. Open a PDF. If another PDF extension opens it first, use Open With… > Lumiere PDF.
