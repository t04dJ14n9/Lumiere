# Obsidian parity observations

Reference: Obsidian 1.15.0, the installed app (`/Applications/Obsidian.app`, `CFBundleShortVersionString` 1.15.0), to be compared by the owner in a disposable vault. Never use the owner's vault. Record date, method, observed result and any issue link in each row. Automated checks do not establish visual or behavioral parity. New rows start not observed.

## Evidence labels

The Status column says what evidence a row has and on which version:

- **behaviour measured on 1.14.4**: a differential probe ran Obsidian 1.14.4 (or, for undated 2026-10-17/18 rows, the Obsidian installed then, 1.14.4) and Lumiere on the same input in a throwaway vault. No 1.14.4 bundle was kept, so these were not re-measured on 1.15.0.
- **code read on 1.15.0**: the shipped 1.15.0 code was read; nothing ran. "partly read" means part of the path was not followed. Where a row was measured on 1.14.4, the read says whether 1.15.0's code still implements the measured rule.
- **not observed running** / **not observed**: no live 1.15.0 observation. **visual parity not observed**: rendering was not compared.
- **no Obsidian equivalent**: the 1.15.0 command or settings catalog has nothing comparable.

Line numbers cite `app.js` from the 1.15.0 `obsidian.asar` (SHA-256 `0e6383301078a798f0f3bdb42bdb606d904ada77eab8c8fc89da533573979248`), extracted with `npx @electron/asar extract` and formatted with Prettier 3.10.1 (`--parser babel`, 178,969 lines). The extraction is read in a scratch directory and never committed. Earlier rows citing `app.pretty.js` lines (2026-11-10) used a different formatting of the same file (153,208 lines).

## Reference version: what changed from 1.13.7 to 1.15.0

Checked 2026-11-21 by comparing 1.15.0's shipped files with the 1.13.7 bundle in `~/Code/obsidian-re/1.13.7` (static; 1.14.4 sits between them and was not available). What matters for Lumiere:

- **Commands.** Four new IDs: `app:increase-font-size` and `app:decrease-font-size` (a pixel a step, 10 to 30; Lumiere's Increase/Decrease Note Font Size follow them), `app:open-file` (desktop file dialog; VS Code has its own) and `app:migrate-frontmatter` (the format converter's frontmatter migration, which replaces the removed `markdown-importer:open`). Default hotkeys are listed under "Verify bindings left unbound".
- **Text size** is kept per device in local storage (`base-font-size`, seeded from the vault's `baseFontSize`) instead of in the vault (DESIGN §15.3).
- **Diagrams.** `lib/mermaid.min.js` is gone. Mermaid syntax is rendered by Pele 1.8.0 (`lib/pele.min.js`, MIT), synchronously, without the guarded-render chrome, vault trust or the dark-theme invert filter. The Mermaid visual measurements made on 1.14.4 (Mermaid 11.13.0) no longer describe the reference; Lumiere still renders with Mermaid (`diagrams` row).
- **Math** ships MathJax 4.1.3 (1.13.7: MathJax 3), the version Lumiere uses.
- **CSS variables.** `app.css` declares 1,228 custom properties against 1,096 (135 added, 3 removed). Added groups: `--bases-kanban-*` (15), `--mermaid-*` (22) and `--pele-*` (26) for diagrams, `--highlight-background` with one per highlight colour and `--highlight-opacity`, and `--tooltip-*`, `--notice-*`, `--tab-*`, `--hotkey-*` and `--setting-item(s)-*` for the interface. Removed: `--text-highlight-bg`, `--text-highlight-bg-rgb` (still honoured as an override of `--highlight-background`) and `--settings-home-background`. The 2026-11-10 static REA (evidence `ev_6656f973c52d9c8d523b697ac6a77957170ffcda27c58103a519f55c9b517b1a`) counted 128 net with a different extraction.
- **Behaviour read in code** that differs from Lumiere is marked in the rows (search the Status column for "differs"). New since 1.13.7: fuzzy search folds Latin, Greek and Cyrillic ё accents (`suggest`; Lumiere follows it since #787), and Swap line moves list items with their children (`swapLineUp`, `swapLineDown`).

## Community plugin compatibility

Obsidian core has no HTML embed. Community plugins do, and notes written for them should still read in Lumiere. They draw the page live inside the note; Lumiere **shows each such embed as a card** (the file's name, Open, Open as Text) and its Open button opens the page in **VS Code's Integrated Browser**, where the window has one. The syntax of the four plugins is read so those notes show the card and not a broken embed. The rows compare Lumiere with what the plugins' published documentation says. This is documentation read on 2026-11-21 and 2026-11-22, not code: no plugin was installed or run, no plugin code was read or copied, and nothing here is a live Obsidian observation. Status is "documentation read; not observed running" unless stated.

Why a card: a probe in VS Code 1.147 (2026-11-22) showed that the vault file's address (`https://file%2B.vscode-resource.vscode-cdn.net/...`) loads in a frame of the editor's page as `chrome-error://chromewebdata/`, a blank box. VS Code serves those addresses only to its own webview documents, and a sandboxed child frame is not one. Owner decision 2026-11-22: no live embed in the note. A first version also showed the page in a webview panel of Lumiere's own (the HTML viewer, #845); a second owner decision the same day replaced it with VS Code's own Integrated Browser, which opens a file by its URI (`workbench.action.browser.openFile`, VS Code 1.147), reloads it as it changes, and needs none of Lumiere's panel, policy or message handling. Cursor and older VS Code builds do not have the command, and there an HTML link opens as text.

Pages read (the plugin listings at community.obsidian.md, and, for Embed HTML, its repository's demo vault):

- Embed HTML (Michael Naumov, id `embed-html`): https://community.obsidian.md/plugins/embed-html; repository https://github.com/mnaoumov/obsidian-embed-html, its README and demo notes "00 Start", "02 Custom Size" and "03 Scroll to Element" (https://raw.githubusercontent.com/mnaoumov/obsidian-embed-html/main/demo-vault/02%20Custom%20Size.md and the like). The demo notes "04 Extract Element", "10 Relative and Full Path", "14 Remote HTML Pages" and "15 Settings" were not read.
- HTML Embed (id `html-embed`): https://community.obsidian.md/plugins/html-embed
- Local HTML Embed (id `local-html-embed`): https://community.obsidian.md/plugins/local-html-embed
- HTML Widget Embed (id `html-widget-embed`): https://community.obsidian.md/plugins/html-widget-embed

The plugins run the page in the note: Embed HTML and HTML Embed with `allow-same-origin` (HTML Embed documents `allow-scripts allow-same-origin allow-forms allow-popups`), HTML Widget Embed without it (`allow-scripts allow-forms allow-modals allow-popups`). Lumiere never runs a page in a note or in a panel of its own: the Integrated Browser is VS Code's, and what the page can reach there is VS Code's to decide, not Lumiere's.
